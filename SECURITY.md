# Security Policy

## Supported versions

Since the project is still early-stage and evolving quickly, we do not yet guarantee long-term support for older versions. We encourage users to run the latest branch or the latest release when available.

## Reporting a vulnerability

If you believe you have found a security issue, please do not open a public GitHub issue.

Instead, contact the maintainers privately through the project discussion or repository owner contact channel.

Please include:

- a summary of the issue
- affected component or file
- reproduction steps if possible
- any suggested mitigation

We will review and respond as quickly as possible.

## Disclosure policy

We ask reporters to:

- avoid public disclosure until a fix is ready
- allow a reasonable response window for remediation
- collaborate with maintainers to assess risk and patch the issue

## Security expectations

Contributors should avoid introducing unsafe code, overly privileged behavior, or unreviewed remote network calls in the early project stages.
